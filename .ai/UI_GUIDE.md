# UI GUIDE

## Purpose

This document defines the visual rules of the Moratta website.

Every page and component must follow these standards.

Consistency is more important than creativity.

---

# Design Philosophy

The interface must communicate:

- Trust
- Professionalism
- Simplicity
- Modernity
- Accessibility

Avoid unnecessary visual effects.

Good design should help users complete actions.

---

# Design Priorities

1. Readability
2. Consistency
3. Accessibility
4. Responsiveness
5. Performance
6. Animations

Animations are always the last priority.

---

# Visual Style

The website should feel:

Modern

Clean

Elegant

Professional

Minimal

Never flashy.

---

# Color Usage

Respect the official Moratta visual identity.

Never invent new brand colors.

Accent colors should only reinforce important actions.

---

# Typography

Hierarchy must be clear.

Use consistent spacing between headings and content.

Prefer shorter paragraphs.

Avoid large text blocks.

---

# Layout

Prefer:

Large white space

Well-defined sections

Consistent vertical rhythm

Balanced alignment

Avoid visual clutter.

---

# Containers

Use consistent max-width.

Maintain equal horizontal spacing.

Respect the established layout grid.

---

# Buttons

Buttons should be visually consistent.

Do not create multiple button styles for the same purpose.

Primary actions must always look identical.

Secondary actions should also remain consistent.

---

# Cards

Cards should follow the same visual language.

Use:

Rounded corners

Subtle shadows

Consistent padding

Consistent spacing

Avoid decorative effects.

---

# Icons

Use Lucide React.

Icons should support content.

Never replace text with icons.

---

# Images

Prefer real property photography.

Avoid generic stock photos whenever possible.

Optimize every image.

Always provide alt text.

---

# Forms

Forms should be:

Simple

Short

Easy to complete

Show validation clearly.

Never request unnecessary information.

---

# Navigation

Navigation must be obvious.

Users should never wonder where to click next.

---

# Mobile First

Every interface must be designed for mobile first.

Then adapt to tablet.

Then desktop.

---

# Responsiveness

Every new component must work correctly on:

320px

768px

1024px

1440px

Never assume desktop first.

---

# Animations

Animations must be:

Fast

Subtle

Purposeful

Avoid long transitions.

Avoid distracting effects.

---

# Loading States

Interactive elements should display feedback.

Examples:

Loading buttons

Skeletons

Progress indicators

Avoid blank screens.

---

# Empty States

When no data exists:

Explain why.

Guide the user.

Offer the next action.

---

# Error States

Errors should:

Explain the problem.

Suggest the solution.

Never expose technical details.

---

# CTA Philosophy

Every page should naturally guide users toward:

WhatsApp

Lead Form

Credit Analysis

Property Visit

Never overwhelm users with too many CTAs.

---

# Accessibility

Respect WCAG principles whenever practical.

Keyboard navigation.

Visible focus.

Semantic HTML.

Readable contrast.

---

# SEO

Design should not harm SEO.

Avoid unnecessary client-side rendering.

Use semantic headings.

---

# Consistency Rule

If a component already exists,

reuse it.

Do not redesign it.

Do not duplicate it.

---

# Golden Rule

The user should feel like the entire website was built by one team,

not by multiple developers.
